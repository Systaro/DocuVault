# Contributing to DocuVault

Thanks for taking the time. Bug reports, reproductions and small fixes help the
most at this stage.

## How this repository works

DocuVault is developed in an internal repository at Systaro, and this GitHub
repository is published from it. Each public commit is a snapshot and lists
the internal changes it contains. That has two consequences for contributions:

- **Issues and discussions happen here.** Please open issues on GitHub.
- **Pull requests are welcome, but are not merged with the GitHub button.**
  A maintainer reviews the PR here, applies the change internally with you as
  co-author, and closes the PR with a link to the snapshot that contains it.

For anything bigger than a bug fix, open an issue first so we can agree on the
approach before you spend time on it.

## Running it locally

You need Docker with the compose plugin.

```bash
cp .env.example .env         # set DB_PASSWORD and JWT_SECRET (openssl rand -base64 48)
docker compose up --build
```

The app is at http://localhost:7031. On the first visit the setup wizard
creates the admin account. The backend listens on http://localhost:7030/api.

Working on one part without rebuilding containers:

| Part | Where | Run | Checks |
|---|---|---|---|
| Backend (Spring Boot, Kotlin) | `backend/` | `./gradlew bootRun` against the compose postgres, redis and minio | `./gradlew test` |
| Frontend (Angular) | `frontend/` | `npm ci && npm start` | `npm run build -- --configuration production` |
| MCP stdio client | `mcp-server/` | `npm ci && npm run build` | |
| Meeting bot | `meeting-bot/` | `docker compose --profile meeting-bot up` | |

## Database changes

Schema changes are Flyway migrations in
`backend/src/main/resources/db/migration`, named `V0NN__what_it_does.sql` with
the next free number. Never edit a migration that has been released.
`db/bootstrap.sql` is generated by `scripts/generate-bootstrap.sh` and only
changes when the Flyway baseline changes.

## Pull request checklist

- The change does one thing, and the description says why.
- Backend tests and the frontend production build pass.
- UI changes come with a screenshot, in light and dark mode if colours changed.
- New user-facing text is English. Every Material icon span carries
  `translate="no"` (see the note in the frontend on browser translation).
- No secrets, customer data or real personal data in code, tests or screenshots.
