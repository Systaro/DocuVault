HTML pages are no longer read-only. They can be edited in the browser,
in the page itself — and nothing is written until you say so.

### Editing a page where it lives

An HTML file used to be something you could look at and nothing else;
changing it meant editing the file locally and pushing it. Every `.html`
page now has an *Edit* button next to its preview, and editing happens
inside the page itself, with the page's own CSS applied. What you edit is
what the page looks like.

The page's own JavaScript is paused while you edit. A page that rewrites
itself on load would otherwise fight your cursor and leave its generated
markup behind in the file.

![Editing an HTML page in place](assets/changelog/v0.5.0/edit-in-place.png)

### The full source, when you want it

The *HTML* tab shows the file exactly as it is on disk — doctype, head,
styles, scripts and all — and edits made there show up in the visual view
when you switch back. Saving only ever replaces the part of the file you
could actually see and edit, so everything outside `<body>` stays exactly
as it was, down to the byte.

![The HTML source tab](assets/changelog/v0.5.0/source-tab.png)

### Nothing is saved behind your back

There is deliberately no autosave here. Rich-text editing works by
letting the browser re-write the page's markup, and browsers are not
careful about it — so the file is only touched when you press *Save*, and
each save is one commit.

While there are unsaved changes, leaving is not quiet about it: closing
the tab raises the browser's own warning, and clicking away to another
document asks first. *Revert* throws the working copy away and puts the
last saved version back.

![Unsaved changes are guarded](assets/changelog/v0.5.0/explicit-save.png)

### Every save is a version you can go back to

The editor has the version history right next to it. Any earlier version
can be opened read-only to see what the page looked like then, and
restored if that is the one you want. A restore is written as a new
version on top of the history, so the state you came from stays
available too.

![Version history and restore](assets/changelog/v0.5.0/versions.png)

### Fixes

- Restoring a version no longer renames the document. The title was
  re-derived from the content on every restore, which only produces the
  right answer for Markdown — an HTML page was renamed to its filename
  each time. This affected the existing Markdown time capsule as well
