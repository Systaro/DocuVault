Files of up to 150 MB can now be uploaded, three times the old limit of 50 MB.
That is enough for a screen recording or a tutorial video, and DocuVault plays
it right in the browser. The limit is the same for the upload button, a folder
dropped onto the file tree and `upload_file` from your AI agent.

![A 120 MB video uploaded to a space, on a scale that now goes up to 150 MB](assets/changelog/v0.8.14/uploads.png)

### Word documents keep their font

A Word document written in a font your computer does not have, such as Aptos or
Calibri, used to show up in a serif font. It now falls back to a font of the
same kind: sans-serif text stays sans-serif, and a document set in Times New
Roman or Cambria stays serif. Paragraphs without a style of their own now take
the document's Normal style, so body text has the size the author chose.

![Two Word documents: one written in Aptos shows sans-serif, one written in Times New Roman shows serif](assets/changelog/v0.8.14/word-fonts.png)

### For self-hosted installs

The bundled nginx-proxy kept nginx's default limit of 1 MB per request, so
larger uploads failed before they reached DocuVault. It now allows 200 MB
through the new `nginx-proxy/uploads.conf`; run `git pull` before `./deploy.sh`
to get it. Behind your own reverse proxy, allow request bodies of 200 MB.
