# DocuVault — Project Notes for Claude

## What this project is

DocuVault is a **self-hosted team documentation tool with Git as the source
of truth**. Every save in the web editor becomes a commit in the team's Git
repo, so documents stay as Markdown files the team can also clone and edit
locally (or hand to an AI agent). It competes with Notion / Confluence, but
without the lock-in. Source-available under BSL 1.1 (see `LICENSE`).

**Stack:**

- **Backend** — Spring Boot 3 / Kotlin / JPA, PostgreSQL 16 + pgvector
  (embeddings), MinIO (attachments, logos, branding), Redis (cache + sessions).
- **Frontend** — Angular 18 + TipTap (WYSIWYG that emits clean Markdown).
- **MCP server** — built into the backend at `/api/mcp` (Streamable HTTP +
  OAuth). `mcp-server/` is the legacy stdio client `@systaro/docuvault-mcp`.
- **Meeting bot** — `meeting-bot/`, Discord + Teams transcription (alpha).
- **Edge** — nginx-proxy + acme-companion (Let's Encrypt) in the product compose.

**Key product surfaces** to keep in mind:

- Git-backed spaces (GitLab sync, or a local repo without remote) with history.
- Roles (Super Admin / Org Admin / Editor / Viewer) plus per-space and team grants.
- Public share links with optional password, view or comment access.
  **Renders embedded HTML / JS deliberately** — see `SECURITY.md`.
- Optional AI (Ask, capture, drafts, semantic search). The UI hides every AI
  feature when no OpenAI key is configured.
- Whitelabel branding per installation (Admin → Branding).
- Tasks and the meeting bot are **alpha**; say so wherever they are advertised.

**Status:** early access. Expect occasional breaking changes in minor versions
until 1.0. Deeper context: `README.md`, `docs/install.md`, `docs/*.md`,
`SECURITY.md`, `CONTRIBUTING.md`.

## Rules that are easy to miss

- **Nothing customer-specific or personal goes into this repository** — not in
  code, test fixtures, docs, screenshots, release-note images or commit
  messages. Use neutral examples (Acme, Alice, Bob, `docs.example.com`). The
  repository and its full history are public.
- **No company defaults in code.** Hosts, mail relays, sender addresses and URLs
  come from configuration (`application.yml` → env), never from a literal that
  only fits one install.
- **Branding:** user-facing text names the product through `BrandingService`
  (`appName()`), tab titles go through `PageTitleService`, colours through
  `var(--primary…)`. Never a literal "DocuVault" or a teal hex in a component.
- **Schema:** changes are Flyway migrations `V0NN__what.sql` with the next free
  number. `db/bootstrap.sql` is generated by `scripts/generate-bootstrap.sh`
  (init.sql + migrations up to the Flyway baseline) — never edit it by hand.

## Cutting a release

1. Release notes in the same commit (below), `APP_VERSION` bumped.
2. Push to `main`, then push the tag **on its own** (GitHub skips workflows
   when more than three tags arrive in one push):
   `git tag -a vX.Y.Z -m "…" && git push origin vX.Y.Z`.
3. `.github/workflows/images.yml` builds `ghcr.io/systaro/docuvault/*` for
   amd64 + arm64 (SBOM, provenance, cosign): `main` → `edge`, a release tag →
   `vX.Y.Z`, `vX.Y`, `vX`, `latest`. Check `gh run list`.
4. `gh release create vX.Y.Z --title "vX.Y.Z · <title>" --notes-file …` with the
   notes body; rewrite image links to absolute
   `https://raw.githubusercontent.com/Systaro/DocuVault/vX.Y.Z/frontend/src/assets/changelog/…`
   (relative paths do not render on GitHub).

Installs upgrade with `./deploy.sh` (no argument = newest release, a no-op when
it already runs). Systaro's own installs are updated by its infrastructure
automation, not from this repository.

MCP client releases: tag `mcp-vX.Y.Z` → `.github/workflows/publish-mcp.yml`
publishes `mcp-server/` to npm (trusted publishing, no token).

### Release notes (the in-app "What's new" dialog)

Every release ships its own notes as a frontend asset, so a self-hosted
install always shows the notes for the version it actually runs.

1. Add `frontend/src/assets/changelog/vX.Y.Z.md` — the notes body in Markdown
   (no heading; the title comes from the index).
2. **Always add conceptual visuals** — one per headline feature, in
   `frontend/src/assets/changelog/vX.Y.Z/<name>.png`, referenced from the notes
   as `![Alt](assets/changelog/vX.Y.Z/<name>.png)` right after that section's
   prose. Notes without visuals are not finished.
3. Add an entry at the **top** of `frontend/src/assets/changelog/index.json`:
   `{ "version": "vX.Y.Z", "date": "YYYY-MM-DD", "title": "…" }`.
4. Bump `APP_VERSION` in `frontend/src/app/shared/version.ts` to match.

**A visual can also be an animated demo.** Write `![Alt](demo:<name>)` on a
line of its own and the dialog renders the matching demo from
`shared/components/changelog-demo.component.ts` (CSS keyframes, holds a still
frame under `prefers-reduced-motion`). Adding one means adding a case to
`CHANGELOG_DEMOS`. Stills remain the default.

**The visuals are conceptual mockups, not product screenshots** — real UI
captures age badly and leak whatever data was on screen. Build them as HTML,
screenshot the element with Playwright, drop the PNG in. The promo scenes in
`promo/gifs/scenes.html` use the same style and can be rendered as stills. House style:

- Canvas exactly **1200×560**, `border-radius: 24px`, background `#f6f6f2`
- White cards `#ffffff`, 1px border `#d4e5e7`, `border-radius: 16px`
- Teal palette: `#388087` (dark), `#6fb3b8` (mid), `#badfe7` (light)
- Text stands in as skeleton bars: `#e8f0f1`, `#c9dcde`; muted text `#7a9a9d`
- Real labels only where they carry the point (a filename, a role, a toggle)
- One idea per image, centred with generous margins

On the next login every user sees the releases newer than their
`users.changelog_seen_version`. A version in `index.json` newer than
`APP_VERSION` is ignored, so notes for an unreleased version can be staged.

## Browser translation (Chrome's "Translate this page")

The UI is English-only, so non-English users read it through the browser's
translator. Two rules keep that from breaking the app:

- **Every `<span class="material-icons">` carries `translate="no"`.** The icon
  name *is* the ligature text, so a translated `add` becomes `hinzufügen` and
  the icon font renders stray letters instead of a glyph.
- **Document content opts out as well** — the TipTap container, the HTML
  editing iframe (`buildFrameDocument`), fenced code blocks, mermaid sources and
  inline code. An editor that reads translated text nodes back would commit the
  translation to Git.

Header labels are `white-space: nowrap` for the same reason.

## Repo layout

- `backend/` — Spring Boot service; `frontend/` — Angular app (markdown viewer
  styles in `frontend/src/styles.scss` under `.markdown-container` /
  `.markdown-readonly`; marked → highlight.js in
  `frontend/src/app/shared/services/markdown-render.service.ts`)

- `docker-compose.yml` — local development (builds from source)
- `docker-compose.product.yml` + `.env.example.product` + `deploy.sh` +
  `db/bootstrap.sql` — the self-hosted install
- `promo/` — landing page (GitHub Pages, `docuvault-promo.systaro.de`), GIF
  sources in `promo/gifs/`
- `.github/workflows/` — CI, images, Pages, npm publish
